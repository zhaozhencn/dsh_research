# 首次研究

本流程来自工作区原任务书的三篇研究与验收要求。新工作区有用户任务书时先吸收其附加约束；没有任务书也能独立执行本流程。

## 基线与盘点

1. 用 `resolve` 获取官方默认分支 HEAD 或用户 ref；保存 resolution JSON。独立 clone/fetch 获取该 SHA，detached checkout 后记录 Git 状态。离线只能研究已获取提交，不能宣称它是当前最新。
2. 用 `snapshot` 输出新的 prepared 目录；核验 workspace 声明与包清单、顶层目录、入口、配置、测试、文档、vendor、生成代码和非 JS 源码。需要时用目标版本包管理器的 workspace list 交叉核对。
3. 建立 coverage 表：目录／包、职责、关键文件、阅读深度、验证方式、所属篇章、遗留问题。深读、概览、按需追踪、排除分别说明；运行验证另设字段。目录清单不证明已读全部源码。
4. 基于 manifest、锁文件、真实导入、服务注入、事件订阅和进程通信分别建立关系。不要把 manifest 依赖图称为全部运行时依赖。
5. 先整理待证问题，再沿真实实现找证据；不要先画理想架构再寻找支持。

## 第一篇：宏观架构

覆盖项目定位、系统边界、实际技术栈、Cordis/Harness/应用载体的责任、插件与服务分类、状态所有权、工程与发布结构。实体名称必须查定义与消费者，不能预设 Session→Turn→Step 是对象嵌套。

追踪所有实际入口如何选择 profile/bundle、应用配置补丁、等待服务、重载及退出。说明不同入口的差别。分析持久事件、运行事件、内存状态、客户端投影、模型上下文、前后端通信及权限强制层。

给出系统边界图、子系统图、模块关系图、生命周期阶段图、实体／状态关系图和架构决策表。图中静态导入、DI、事件、IPC 用图例区分。分析取舍须注明前提；无测量不能给性能排名，无作者说明不能编造动机。

## 第二篇：动态运行

从用户输入沿实际符号追踪：预处理→入队／唤醒→接纳→上下文／历史／工具 schema→路由→模型适配→流式响应→工具／审批→结果提交→继续或终止。

每个环节记录入口、调用方、执行主体、状态所有权、异步等待点、事件派发语义、持久化提交点、错误表达、重试范围和取消传播。定位监听器与 producer；不能停在接口或事件类型声明。

至少逐项分析九类场景：

| 场景 | 需要回答 |
|---|---|
| 启动与退出 | 配置、挂载、服务就绪、失败与清理 |
| 单轮流式对话 | 开始／提交／结束、无 Step 路径 |
| 工具与多 Step | 选取、参数、审批、并发、回写、下一轮 |
| 模型失败／流中断 | 重试是否重组输入、取消落到哪里 |
| 工具失败／拒绝／超时 | 部分成功、缺失结果、副作用是否可回滚 |
| 追加输入与并发 | 接纳窗口、队列、同会话与跨 Agent 约束 |
| 卸载／配置／代码更新 | 撤销注册、在途任务、状态、重启需求 |
| 读取／恢复／分支／中断 | 投影、格式与迁移、是否重新调用模型或工具 |
| 前端订阅与重连 | 流、断线、重建／补偿机制及缺口 |

场景记录触发输入、前置条件、入口、真实调用链、事件／状态、提交点、结果、失败分支、证据和验证层级。不存在或无法运行的路径明确说明。关键场景画 Mermaid 时序图，图中名称直接来自固定 SHA。

## 第三篇：扩展与决策

列真实扩展点和组件替换矩阵：定义与实现、API／事件／配置、参数／返回值、执行时机、作用域、顺序、依赖、错误与清理责任、接口稳定性、生效方式、在途任务和兼容风险。

逐项评估模型、工具、Loop、会话、UI、日志、存储；“可以导入”不等于稳定公开接口，“可以卸载”不等于运行中安全替换。优先配置／公开插件契约，必要时说明修改内部实现的理由与升级成本。

给出专属 Agent、私有工作台、多用户与多 Agent 平台方案，区分原生能力和新增身份、隔离、凭据、队列、恢复、审计、运维工作。工作量只用有理由的相对评估，不能捏造人日或吞吐量。两个独立扩展示例遵循 validation.md。

问题表区分已确认问题、潜在风险、通用建议，包含适用 SHA、触发条件、现象、成因、证据、规避和验证状态。使用契约约束和设计取舍不自动算缺陷。阶段计划包含目标、原生依赖、新增工作与验收条件。

最后按 artifacts.md 输出完整三篇、公共附录、示例和可复现记录；完成结构检查与语义自查，逐项说明限制。
