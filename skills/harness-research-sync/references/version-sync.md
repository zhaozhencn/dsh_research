# 版本同步

同步目标是让已有研究可独立解释目标版本，并保留历史证据。不是用新 SHA 批量替换旧链接。

## 选择旧版与目标

1. 用户指定旧成果优先。否则检查根目录和 versions 下的 baseline/research-state，只选 complete；旧成果缺 state 时标 legacy-ungraded，复核其实际完整性。存在多条分支时根据 repository、ref、SHA 和提交祖先关系选与目标相关的最近基线，必要时说明选择理由。prepared 文件夹不参与选择。
2. 最新默认指调用时官方默认分支 HEAD，用 `resolve --out <全新resolution.json>` 保存发现时间与 SHA。指定稳定发布时核验官方 release/tag，不把默认分支当 stable。带注释 tag 使用 peeled commit；同名 branch/tag 必须明确完整 ref。
3. 新建独立 clone 或自有工作区 worktree；获取旧、新提交和所需历史。不得切换或清理用户开发检出。固定 SHA 后不再追逐上游变化；若 fetch 与 resolve 之间 HEAD 前进，只获取已解析 SHA。
4. 检出失败、权限或网络受限时研究已获取提交并标非最新／目标未获取。不得把缓存当实时最新。来源改名、归档、远程变化须说明，不能静默改用非官方 fork。
5. 输出版本子目录；重跑遇到已有目录另加后缀，不覆盖旧版。源码检出与报告分开。

## 建立差异与影响闭包

用 `snapshot --previous` 生成全量新盘点、文件差异、提交范围、manifest 影响与证据候选。非祖先关系用两棵树比较并说明分叉，不能把 old..new 日志等同线性升级历史。浅克隆信息不足时获取足够历史后再判断。

比较包增删／改名、公开导出、配置 schema／默认值、profiles、依赖与锁文件、原生组件、事件参数／顺序、服务名／scope、持久格式／迁移、模型映射、客户端投影、测试和示例。相邻文件未改也可能是消费者，必须沿实际导入、DI、事件与配置扩展影响范围。

| 差异 | 复核动作 |
|---|---|
| provider／工具／路由 | 定义、消费者、注册、重试／取消、结果回写 |
| Loop／输入 | 正常与异常链、接纳窗口、提交点、并发 |
| 持久状态／格式 | 写读、恢复、投影、迁移／分支、副作用 |
| Cordis 或其他依赖 | 锁定版本源码、事件／DI语义、peer 单实例 |
| profile／默认配置 | 不同入口的组装、覆盖／删除、就绪与清理 |
| UI／协议 | 服务端 producer、传输、客户端重建、断线 |
| 测试／文档改动 | 覆盖是否新增、实现是否一致；说明不是证明 |

提交说明只用于定位设计问题；作者动机需要明确说明，行为需要实现或运行证据。包清单没有变也不能跳过锁文件或运行链。

## 复核证据与结论

读取 evidence-status：identical-text、reanchored-identical-text、changed、ambiguous、missing、invalid-previous 均从 pending 开始。运行／推断等非源码锚点不会因文本匹配续期，必须重新建立依据。多处重复片段必须由执行者逐项进行语义定位，不能自动取第一次；本任务不要求用户参与。

对旧主要结论建立稳定 claim ID，分类 new/modified/retained/removed/uncertain，记录旧结论、新结论、原因、新证据和 reviewed_at_sha。保留项也要检查未变消费者与配置假设；删除项记录目标版的替代实现、配置或相关源码与 diff 依据，不能仅凭搜索没命中。只在 delta 的明确比较区引用旧 SHA；当前正文和当前证据 ledger 指新 SHA。

旧版 evidence 没有逐条 SHA、hash 或 review_status 时只导入 path/range/symbol 等定位线索；legacy 标识不能伪装已复核。复核后重建新版本 evidence.json，不能直接把 evidence-status 改名为证据表。

## 验证、报告与交付

先迁移两个独立示例，查新 API、导出、peer 范围、配置与实际安装行为；契约已删除时给出受支持替代并说明能力变化。重新验证受影响测试、正常与异常链和资源撤销。所有新运行记录绑定目标 SHA；旧日志仅作历史对照。

生成完整的新三篇与五个公共附录，delta 汇总版本范围、重大变化、迁移建议、证据复核、验证结果和未解决问题。重点关注“曾成立但新版本不再成立”的强结论。更新覆盖记录，不能把旧 read_paths 直接标新 SHA 深读。

新旧 SHA 相同：记录无上游变化，保留旧事实，按本次明确 scope 复核／补验证／修正文稿。不得制造版本差异；若没有重新跑测试，应明确引用的是同 SHA 的历史环境记录，不能说本次环境通过。若选择生成完整新版成果，仍遵循 --final 的当前运行台账约束。

--final 校验通过后再做证据语义、图表顺序和报告完整性自查，才将 state 改 complete。失败、阻碍和跳过均保留，未能实测的行为降级描述；按 artifacts.md 标明 limited 的原因。
