# 插图：表达真实关系，放在读者需要的位置

## 图型先于绘图

|理解任务|优先图型|校对重点|
|---|---|---|
|理解入口和职责|整体地图|装配、执行和存储是否被误画成一次顺序执行|
|跟随caller与callee|时序或调用图|实线调用、虚线事件、返回与读取的含义是否显式|
|理解Turn／Step／attempt|嵌套或带循环的图|包含与重复不等于必经单向流程|
|理解关键交接数据|数据契约／生产消费图|真实字段、闭包和继承是否分开|
|理解owner、寿命和状态|泳道／状态图|等待、完成、提交、释放是否各有边界|
|理解拒绝与恢复|条件分支图|触发条件、返回点和终止分支是否都有证据|
|理解并列表示或成本归集|关联图／表格|不要加箭头暗示不存在的先后关系|

图中每个源码符号都应在正文或计划中有证据。示意名称可以缩写，但必须标成说明性标签；不能省略命名空间后伪装为一个实际方法。公开字段、局部变量、捕获闭包和扩展建议分别标识。

## 位置与文案

长篇源码专栏可安排整体、交接、数据、分支四张图。先服从用户图片数量要求；没有要求时按内容需要调整，避免用换色的同一流程凑数。

- 整体图靠近开篇机制描述，让读者带着地图进入细节。
- 交接图紧邻caller／callee转换，解释参数、结果或事件怎样传递。
- 数据图放在结构介绍附近，便于对照声明与字段表。
- 分支图放在异常或资格判断附近，配合条件和回到主线的位置。

相邻文字先说明为何需要这张图，图注再说明它表达什么、省略什么，图后继续沿同一个对象推进。不要集中把所有图片放在结尾，也不要固定“每三个步骤插一图”。Agent、Turn、Step、attempt、Inbox等原语和源码标识在正文与图中保持一致。

## 渲染与复核

技术关系图优先用可编辑定义和确定性绘图工具。PNG和SVG共享文字、坐标、图序与标签，字体可配置，检查文字宽度、断行、画布高度、节点边界和缩小后的阅读性。向量图和栅格图均应可追溯到同一份定义。

保存图文件后检查引用是否存在、PNG能否解码、SVG是否为有效XML；再实际查看整体输出与关键细节。机器检查无法证明箭头正确或图中文字足够清晰。图示改变时同步正文图注、清单与导航，不改写历史图示检查结论。

若项目已有渲染器和图清单，复用其入口；不要为每篇另建风格不一致的绘图代码。发布平台预览只在任务包含该范围时执行，未预览不能说已经符合最终排版。
