# 证据、保留范围与同步验证

## 保存原状，保护未选中内容

开始编辑前，将目标文章交给 `snapshot`，将不应变化的样篇、邻近文章和图片交给 `--protect`。辅助脚本只接受root内的相对文件路径，拒绝重复或重叠范围；基线输出文件采用独占创建，避免覆盖历史记录。

同SHA深化默认保留二级标题、`### 步骤1...`／`### 第一步...`／`### Step 1...`编号标题以及全部既有代码块。`compare`对代码块使用hash多重集合，重复摘录减少也会报告失败。图片数量只有通过 `--images` 显式给出时检查；它不证明图序、位置、图内术语或正确性。

标题措辞改变但领域不变时选择 `--headings same-count` 或 `--steps same-count`，记录新旧主题对应并逐项语义复核。结构调整须符合当前用户授权；不能用 `any` 掩盖越界修改。版本变更需要替换旧摘录时可选择 `--code-policy any`，但必须解释移除或改写的原因并重新查证当前全部代码。

脚本识别常规行首Markdown标题、反引号／波浪号围栏和行内图片语法。它不是完整CommonMark解析器，不解析HTML图片、引用式图片、缩进代码块或复杂嵌套Markdown。遇到未闭合围栏会失败。项目若使用这些语法，补充合适解析器或现有检查器，不能凭本脚本图片数判定全部资产。

## 源码原文

`extract`使用 `git rev-parse` 和 `git show FULL_SHA:path` 读取提交对象，不使用可能已修改的工作树。输出完整SHA、文件路径、行范围、`raw`、仅统一公共缩进的`code`以及两者的SHA256。hash以选段按LF连接且无末尾换行的UTF-8内容为准，不是整个Git blob的hash。

路径与行号必须精确，范围应覆盖声明或分支且不混入无关代码。可显式提供 `--base-url https://github.com/owner/repo` 生成固定提交链接；脚本不猜远端、不联网、不自动验证URL对应本地仓库。说明和摘录是否匹配仍由执行者核对。

## 两类验收分别记录

|自动检查|执行者独立的语义复核|
|---|---|
|SHA、范围、原文与hash|结论是否确由摘录与consumer支持|
|标题、步骤、原文保留|原有领域是否保留，调用切换是否连贯|
|保护文件字节一致|修改范围是否满足用户指令|
|链接、图序、解码与尺寸|图的节点、边、条件、术语与正文是否准确|
|清单及当前数量|独立阅读是否能理解前提、机制与心得|
|命令、退出码、日志|本轮验证与历史、推断、建议是否区分|

为每篇记录已经复核的调用、字段、生命周期、图示和结尾，发现问题后修正文稿再重跑受影响检查。机器通过不能替代语义复核；测试、代码块和图片数量不是文章深度指标。

## 选择实际需要的检查

同SHA编辑运行文稿、链接和资产检查。源码、示例、配置改变时再运行相应类型、构建和行为测试。既有测试可以作为明确标注SHA的历史证据，不能写成本轮重新通过，也不能自动继承给新版本。

DeepSeek Harness研究仓库若仍提供以下脚本，可在仓库root运行；这些路径是案例，不是本技能在其他项目的前提：

```sh
.sources/column-work/.venv/bin/python research/deepseek-harness/validation/check-column.py
node research/deepseek-harness/validation/check-artifacts.mjs
python3 -m unittest discover -s skills/source-code-article-refiner/scripts -p 'test_*.py' -v
```

每次检查保存命令、退出码、范围、失败及后续修复，不覆盖旧失败日志。当前清单可更新，历史批次不重写。修改后无需反复运行无关的历史runtime测试；若当前证据不足，则明确写出限制。

## 最终交付

提供完整当前文章、可编辑图定义与图片、导航／当前清单和验证记录。简要说明实质改善、来源基线、实际检查与剩余限制。方法文档或技能创建不等于执行了一次完整文章优化，更不等于外部发布。
